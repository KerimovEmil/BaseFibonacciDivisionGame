# Base Fibonacci Division Game 2.0 — Design Spec

_2026-06-03_

## Goal

Transform the bare pygame prototype into a beautiful, intuitive, feature-complete
puzzle game that runs on **desktop (pygame)** and **web (pygbag/WASM)**, with a
gorgeous README and screenshots.

## What the game is

A Zeckendorf (base-Fibonacci) division puzzle. A dividend `N = divisor × quotient`
is seeded as tiles in the bottom row (its Zeckendorf representation). The player
rearranges tiles using four Fibonacci-identity-preserving moves so that exactly the
"solution cells" — the outer product of the divisor's and quotient's Zeckendorf
representations — each hold one tile. The grid value is invariant: a tile at
(row label `F_r`, col label `F_c`) is worth `F_r · F_c`.

The four moves (labels descend left→right and top→bottom, so smaller indices = larger F):

- **RIGHT / DOWN (split):** `F_n → F_{n-1} + F_{n-2}` (one tile becomes two neighbours).
- **LEFT / UP (merge):** `F_{n-1} + F_n → F_{n+1}` (two adjacent tiles become one).
- Edge special cases on the bottom row / last column halve-and-carry (value 2 → 1 + carry).

## Architecture

Async, scene-based, web-safe. Retire the blocking `while True` loop, the Event
subclass hierarchy, `UpdateGameScreen`, and the `pygame_menu` dependency.

## Key designs

### rules.py (single source of truth)

`is_valid(state, row, col, direction) -> bool` and
`apply(state, row, col, direction) -> new_state` operate on a plain
`list[list[int]]`. `move.py` mutates the live grid by calling these; `solver.py`
explores with these. Guarantees gameplay and solver never disagree.

### solver.py

- State = `tuple(tuple(row))`. Goal test = grid win condition expressed on state.
- BFS from start; neighbours = every (non-empty cell × 4 dirs) that `is_valid`.
- Visited set + `MAX_NODES` cap (e.g. 200k) → returns shortest move list or `None`.
- `hint(grid)` = first move of the path. `solve(grid)` = full path for animation.

### Interaction & visuals

- Tiles: rounded squares, soft shadow, subtle vertical gradient; number badge for
  counts >1. State colours: start, live, on-target (locked-in), and empty target slot
  (glowing dashed outline).
- Pick up a tile → its legal destination cells highlight (real `ShowValidMoves`).
- Moves animate (ease-out tween ~140ms). Drag shows a translucent ghost.
- HUD: banner "Build N = a × b", Moves, Timer, Best (per-puzzle, in-session),
  button bar: Undo · Redo · Reset · Hint · Solve · New · Mute · Menu. Collapsible move log.
- Win: confetti burst + overlay (moves, time, optimal-move count, Play Again / Menu).

### Difficulty

Easy/Medium/Hard → (lower, upper) integer ranges feeding `Problem`, controlling grid
size and tile count.

### Sound (web-safe)

`sound.py` wraps `mixer`; every load/play in try/except; global mute. Convert the 3
mp3s to `.ogg` (ffmpeg) for reliable web playback; fall back gracefully if mixer absent.

### Web build

`pygbag main.py` produces `build/web`. README documents `pygbag main.py` (local
test server) and the static output for hosting. Async loop + no blocking mainloops
make this work.

## Testing

- `tests/test_util.py` (keep).
- `tests/test_rules.py` — pure `apply` equals `Move` mutation; invalid moves rejected.
- `tests/test_solver.py` — solver finds a path; replaying it reaches a win; a solved
  board is detected as win in 0 moves.
  All run headless via `SDL_VIDEODRIVER=dummy`.

## Out of scope (documented as future)

Online leaderboards, account system, alternate rule-set injection (left as a
designed extension point in `rules.py`).
